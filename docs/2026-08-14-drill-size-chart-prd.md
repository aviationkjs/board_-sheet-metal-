## 1. 배경

`info.html` 은 Huck Gun · Fastener 관계표를 담고 있었으나, 현장에서 실제로 자주 찾는 것은 **드릴 사이즈**다. 판금 작업 중 "이 리벳엔 몇 번 드릴?", "1/8 인치가 몇 mm?" 를 확인하려면 매번 인쇄물이나 검색에 의존해야 했다.

이를 **번호 드릴 + 분수 드릴을 지름 순으로 통합한 표** 하나로 대체하고, 현장 메모·클리코 색·참고 사진을 항목별로 붙일 수 있게 한다.

## 3. 목표 / 비목표

### 목표
1. No.1~40 + 분수 1/64~1/4″ 를 **하나의 지름 순 표**로 통합한다.
2. 인치 소수 ↔ mm ↔ 근접 분수를 **동시에** 보여 환산 단계를 없앤다.
3. 모바일에서 **위에서 아래로 스크롤하며 전체를 훑을 수** 있게 한다.
4. 항목별 **자유 메모 · 클리코 색 · 참고 사진**을 붙일 수 있는 구조를 만든다.
5. 사진 파일이 **하나도 없어도 표가 완전히 동작**해야 한다. (단계적 채우기)

### 비목표
- Letter drill, 탭 드릴, 나사 하부 구멍 표 (v2 이관)
- RPM·이송 계산
- 일반 사용자 편집 — 읽기 전용 (편집은 관리자만, §11)
- 로그인 요구 — `divider.html` 과 동일하게 불필요

## 4. 핵심 설계 — 표 하나, 폭에 따라 열이 접힌다

v1.0~v1.3 은 **차트 모드(세로 목록 4열)** 와 **상세 모드(8열)** 를 토글로 오갔다. 두 모드가 사실상 같은 데이터를 보여주는 데다, 폰에서는 늘 차트 모드만 쓰게 되어 **차트 모드를 없애고 표 하나로 합쳤다.**

대신 **화면 폭에 따라 열이 접힌다.** 접힌 열의 값은 행을 탭했을 때 뜨는 하단 시트에서 모두 볼 수 있다.

| 화면 폭 | 보이는 열 |
|---------|-----------|
| **≤767px (폰)** | `넘버` · `분수` · `INCH` · `메모` (관리자면 `수정`) |
| **≥768px** | `넘버` · `분수` · `INCH` · `mm` · `메모` · `클리코` · `사진` (관리자면 `수정`) |

### 4-0. 넘버·분수를 나란히 — v1.7

v1.6 까지는 `표기` 한 열에 `#30` 또는 `1/8″` 중 **하나만** 나왔다. 넘버와 분수를 함께 넣으면 넘버가 분수를 덮었다. 이제 **두 열로 분리**해 서로 덮지 않는다.

```
넘버    분수        INCH     메모
#30    ≈ 1/8″      .1285   AD4 1/8″ 리벳     ← 기본 번호 드릴 (분수는 계산값 ≈)
—      1/8″        .1250   —                ← 기본 분수 드릴 (넘버 공란)
#21    5/32″       .1590   —                ← 둘 다 넣은 추가 행 (둘 다 표시)
—      —           .2035   —                ← INCH 만 넣은 추가 행 (나머지 공란)
```

- **직접 넣은 분수**는 밝게, **계산된 근접 분수**는 `≈` 를 붙여 흐리게 — 정확값과 근사값이 구분된다.
- 오차 `(+.0035)` 는 PC 에서만 함께 보이고, 폰에서는 접혀 시트에서 확인한다.
- **같은 지름·표기의 행을 추가해도 기존 행은 지워지지 않는다.** 두 줄이 나란히 남고, 저장 전 확인창으로 알린다.

```
폰 (375px)                         PC (1280px)
표기   INCH   근접분수  메모        구분 표기  inch  mm   근접분수       메모           클리코 사진
#21   .1590  5/32″   AD5 5/32″ 🖼   No. #21  .1590 4.04 5/32″(+.0028) AD5 5/32″ 리벳 ●검정  🖼
5/32″ .1563    —       —           Frac 5/32″ .1563 3.97 —            —              —     —
#30   .1285  1/8″    AD4 1/8″ 🖼    No. #30  .1285 3.26 1/8″(+.0035)  AD4 1/8″ 리벳  ●구리  🖼
```

- 번호와 분수가 **지름 순으로 섞여** 표시되므로 "이 지름 근처에 뭐가 있나"를 바로 본다.
- 폰에서는 근접 분수의 **오차 `(+.0035)` 가 접히고** 분수만 남는다. 오차는 시트에서 본다.
- 폰에서는 사진 열이 접히는 대신 **메모 뒤에 `🖼`** 가 붙는다.
- **아무 행이나 탭하면 하단 시트** — mm · 근접 분수 오차 · 클리코 · 사진까지 전부.
- 위에서 아래로 스크롤하면 56행이 전부 지나간다 (폰 약 3.2 화면).

### 4-1. 표 헤더 고정 — v1.3 버그 수정

v1.3 까지 폰에서 **헤더 행이 표 안쪽으로 밀려 내려가 행 위에 겹쳐 보이는 버그**가 있었다.

- **원인**: 표를 감싼 `.table-wrap` 에 `overflow-x:auto` 가 걸려 있었다. `overflow` 가 붙으면 그 요소가 **스크롤 컨테이너**가 되고, 안쪽 `position:sticky` 는 뷰포트가 아니라 **그 컨테이너 기준**으로 붙는다. 헤더에 준 `top:188px` 이 컨테이너 안쪽 188px 지점으로 해석돼 헤더가 표 중간에 떠 있었다.
- **해결**: `overflow` 를 아예 걷어냈다. 대신 좁은 화면에서 **열을 접어 표가 화면 폭에 들어가게** 만들어 가로 스크롤 자체를 없앴다.
- 결과: 280~1280px 전 구간에서 헤더가 컨트롤 바 바로 아래에 정확히 붙는다(오차 0px). 가로 스크롤도 없다.

## 5. 데이터 사양

### 5.1 행 — 총 65개

| 분류 | 개수 | 범위 | 비고 |
|------|:----:|------|------|
| Number drill | **40** | #1 (.2280) ~ **#40 (.0980)** | 제공 데이터. **ANSI 표준값과 전량 대조 완료.** #41~#80 은 `MAX_NO` 로 제외 |
| Fraction drill | **16** | 1/64″ (.0156) ~ 1/4″ (.2500) | 코드에서 `n/64` 로 생성 → 오타 불가 |
| **패스너 홀** | **9** | .1290 ~ .3125 | 홀 사이즈표에서 옮김. 표준 드릴에 **없는 지름만** 별도 행 (§5.4) |

> 데이터 배열에는 **#80 까지 그대로 보존**돼 있고 `MAX_NO = 40` 으로 잘라 쓴다. 숫자 하나만 바꾸면 범위가 넓어진다.

### 5.2 열 — 8개

| # | 열 | 출처 | ≥768px | ≤767px (폰) |
|---|-----|------|:------:|:-----------:|
| 1 | 구분 (No./Frac) | 자동 | ✅ | 접힘 → 시트 |
| 2 | **표기** (`#30`, `1/8″`) | 자동 | ✅ | **✅** |
| 3 | **인치** (토글 시 mm) | 데이터 | ✅ | **✅** |
| 4 | mm | 자동 (×25.4) | ✅ | 접힘 → 시트 |
| 5 | **근접 분수** | 자동 | ✅ (오차 포함) | **✅** (오차만 접힘) |
| 6 | **자유 메모** | 입력 | ✅ | **✅** |
| 7 | 클리코 색 | 입력 | ✅ | 접힘 → 시트 |
| 8 | 사진 | 파일 | 🖼 버튼 | 메모 뒤 `🖼` → 시트 |

### 5.3 데이터 구조

`info.html` 안 인라인 JS. (외부 JSON `fetch` 는 `file://` 로 열 때 CORS 로 막히므로 인라인이 안전)

```js
const EXTRA = {
  "#40": { memo:"AD3 3/32″ 리벳", cleco:"silver", photo:"drill-40.jpg" },
  "#30": { memo:"AD4 1/8″ 리벳",  cleco:"copper", photo:"drill-30.jpg" },
  "#21": { memo:"AD5 5/32″ 리벳", cleco:"black",  photo:"drill-21.jpg" },
  "#11": { memo:"AD6 3/16″ 리벳", cleco:"brass",  photo:"drill-11.jpg" }
};
```

- 키는 행 종류별로 다르다.

  | 행 | 키 | 예 |
  |---|---|---|
  | 넘버 드릴 | `#`+번호 | `"#40"` |
  | 분수 드릴 | 기약분수+`″` (U+2033) | `"1/8″"` |
  | **INCH 만 있는 행** | **소수 인치** | `".2600"` `"0.2600"` `".26"` |

- **INCH 키는 문자열이 아니라 숫자(1/10000 인치 반올림)로 맞춘다** — `".2600"` · `"0.2600"` · `".26"` 이 모두 같은 행에 붙는다. v1.8 까지는 문자열 일치라 `"0.2600"` 같은 표기가 **조용히 무시**됐다 (v1.9 수정).
- 필드는 전부 선택. 없는 항목은 표에 자동으로 표시되지 않는다.
- 초기 4개는 리벳 규격이 확정된 항목만 넣었다. **불확실한 값은 채우지 않았다** — 잘못된 드릴을 잡으면 소재를 버리기 때문.

### 5.4 패스너 홀 사이즈 — v1.8

현장 홀 사이즈표(사진)의 **패스너 28종**을 표에 넣었다. 값은 1/10000 인치 표기를 그대로 옮겼다 (`1290` → `.1290″`).

**정리 규칙 — 중복 제거**

1. **같은 지름을 쓰는 패스너는 한 줄로 묶는다.** 28종 → **17개 지름**
   예) `.1610` → `MS20426AD5 · C10001AD5 · MS20470AD5`
2. **기존 드릴과 지름이 정확히 같으면 새 행을 만들지 않고 그 행 메모에 붙인다.** (8개)

   | 붙인 행 | 지름 | 메모 |
   |---|---|---|
   | `#20` | .1610 | MS20426AD5 · C10001AD5 · MS20470AD5 |
   | `#15` | .1800 | C9502-05 |
   | `#12` | .1890 | NAS4452S06 · NAS4450S06 |
   | `#11` | .1910 | 기존 `AD6 3/16″ 리벳` **뒤에 이어 붙임** + MS20426AD6 · MS20470AD6 · C20645-3 · NAS1581 |
   | `#8` | .1990 | MS90353S06 · MS90354S06 |
   | `#7` | .2010 | NAS6203-8 |
   | `5/32″` | .1563 | NAS7035H |
   | `1/4″` | .2500 | C20645-4 |

3. **표준 드릴에 없는 지름만 새 행**으로 넣는다. (9개 — `.1290 .1310 .1620 .1635 .1640 .1895 .2030 .2600 .3125`)
   넘버·분수가 없는 치수이므로 **두 칸은 공란**이고 INCH·메모만 채워진다.

**근접 분수 표시 규칙 (v1.8 통일)** — 넘버·분수가 모두 없는 'INCH 만' 행은 표에서 분수 칸이 **공란**이다. 관리자가 손으로 넣은 INCH-only 행과 동작이 같다. 근접 분수는 **행을 탭하면 시트에서** `≈ 17/64″ (+.0006″)` 형태로 확인한다.

> **출처 주의:** 값은 현장 홀 사이즈표 **사진을 읽어 옮긴 것**이다. 원본 표기가 `1290-` 처럼 범위의 **하한만 보이는 형태**여서 하한값을 채택했다. `NAS1921@04` 의 `@` 는 사진에서 판독이 어려운 문자를 그대로 옮긴 것이다. 현물과 대조해 확인하시고, 다르면 관리자 화면에서 바로 고칠 수 있다.

## 6. 사진 팝업 사양

### 6.1 동작
1. 표의 `🖼` 버튼(PC) 또는 하단 시트의 `사진 보기` 를 누른다
2. 중앙 모달 + 배경 흐림, 제목(표기 · 메모) / 사진 / 설명(선택) 구성
3. 닫기: `✕` · 배경 탭 · `ESC`
4. 사진은 **모달을 여는 순간 처음 로드** → 초기 페이지 로딩과 무관
5. **파일이 없으면** 깨진 이미지 대신 "사진 준비 중입니다 + 넣어야 할 경로" 안내 카드

## 7. 검색 · 필터 · 정렬

| 기능 | 동작 |
|------|------|
| 검색 | `30` · `.128` · `1/8` · `3.26` · `리벳` · `구리색` 전부 매칭 |

### 9.1 상태바 이름 표기 — v1.4

바깥(메뉴·탭 제목)과 안(상태바)의 이름이 달라 헷갈린다는 지적에 따라 **`Fastener Drill Reference Table` 로 통일**했다.

- 상태바 이름은 **런타임에 실제 폭을 재서** 다 들어가면 전체 이름을, 모자라면 **`FDRT`** 로 바꾼다. 하드코딩한 분기점이 아니라 측정값이라 기기·폰트가 달라도 알아서 맞는다.
- 웹폰트(IBM Plex Mono)는 늦게 도착하면 글자 폭이 달라지므로 `document.fonts.ready` 후 한 번 더 잰다.
- 실측: **360px 이상에서 전체 이름**, 320px 이하에서 `FDRT`. 일반적인 폰(375~430px)은 전체 이름이 나온다.

### 9.2 보드 헤더 (`index.html`) — v1.3

버튼이 5개까지 늘어나 폰에서 줄바꿈되던 헤더를 **2개로 줄였다.**

```
이전:  [🟨 스티커 ▾] [📦 자재소모] [🔄 사역표: 홍길동 ▾] [⋯]
이후:  [🟨 스티커 추가] [⋯]
```

`⋯` 더보기 안의 순서 — 이번 순번(정보) · 전체 사역표 보기 · 자재소모 · **Fastener Drill Reference Table** · FT-200_Guide · 균등분할 계산기 · 전투기 런 게임 · (관리자: 회원 관리 · 로그 조회) · ─── · 전체삭제 · 로그아웃

- 가장 자주 쓰는 **스티커 추가만 한 번에 닿게** 두고, 나머지는 전부 한 곳으로 모았다.
- 파괴적 항목(전체삭제·로그아웃) 앞에 구분선(`.drop-item.sep`)을 둬 오조작을 줄인다.
- 드롭다운 폭은 `min-width 215px / max-width min(300px, 100vw − 24px)` 로, 긴 영문 이름이 들어가도 화면 밖으로 나가지 않는다. (375px 기준 폭 238px, 화면 안)
- 제거된 `stickerMenuBtn` · `dutyMenuBtn` · `dutyCurrentLabel` 관련 코드는 `app.js` 에서 함께 정리했다. 이번 순번 표시는 더보기 상단 `drop-info` 로 유지된다.

## 11.5 관리자 행 추가 · 편집 — v1.5

### 11.5.1 권한
- `localStorage.username === "admin"` 일 때만 관리자 UI가 뜬다. (보드·자재소모와 동일한 판별 방식)
- **비로그인 사용자도 표는 그대로 열람**한다 — 이 페이지는 여전히 로그인을 요구하지 않는다.
- 추가된 행은 **모두에게 보인다.** 편집·삭제만 관리자 전용.

### 11.5.2 입력 규칙

| 필드 | 필수 | 형식 | 검증 |
|------|:----:|------|------|
| **INCH** | **✅** | 소수 `.1285` 또는 분수 `1/8` | `0 < inch ≤ 4`. 4 초과 시 "mm 로 넣으신 건 아닌가요?" |
| 넘버 | | 정수 | 1~200 |
| 분수 | | `1/8` | `n/d` 형식 |
| 메모 | | 자유 | — |
| 클리코 | | 4색 중 선택 | — |
| 사진 파일명 | | `drill-30.jpg` | `assets/photos/` 기준 |

**표기(label) 결정 순서** — 넘버가 있으면 `#30`, 없고 분수가 있으면 `1/8″`, 둘 다 없으면 **INCH 값 자체**(`.2570`)가 표기가 된다. 그래서 **INCH 하나만으로도 행이 성립한다.**

- 입력 중 **미리보기**가 "표기 · inch · mm · 근접 분수"를 실시간으로 보여줘, 저장 전에 표에 어떻게 들어갈지 확인할 수 있다.
- **중복 경고 2종** (막지 않고 확인만 받는다)
  - 같은 **지름**이 이미 있을 때 → `같은 지름(.1285″)인 #30 이(가) 이미 있습니다`
  - 같은 **표기**가 이미 있을 때 → `표기가 #1 인 행이 이미 있습니다 (.2280″)`

### 11.5.3 편집 · 삭제 — 기본 행 포함 (v1.7)

관리자에게는 **모든 행 오른쪽에 `✎` 버튼**이 붙는다. 행을 탭해 시트에서 들어가도 된다.

| 대상 | 수정 | 삭제 | 복구 |
|------|------|------|------|
| **추가 행** | 값 전체 | 실제 제거 | 없음 (되돌릴 수 없음) |
| **기본 56행** | 값 전체 | **숨김** (표에서 감춤) | `↩ 복원` · `↩ 표준값으로 되돌리기` |

기본 행은 코드의 ANSI 표준값을 원본으로 두고, 수정분을 `drill_overrides` 에 **덮어쓰기 레이어**로 얹는다. 원본은 지워지지 않으므로 언제든 되돌릴 수 있다 — 실수로 표준 규격을 망가뜨려도 복구된다.

- 수정한 기본 행 → **앰버 띠** + 시트에 `표준값으로 되돌리기`
- 숨긴 기본 행 → **관리자에게만** 흐리게 + `숨김` 배지로 보이고, 일반 사용자에게는 안 보인다
- 추가한 행 → **초록 띠**
- 관리자 바에 `추가 2 · 수정 1 · 숨김 1 행` 처럼 현재 변경 상태를 요약한다

### 11.5.4 저장소 · 규칙

추가 행은 Firebase RTDB `drill_rows` 에 저장된다. **규칙을 콘솔에 게시해야 저장이 된다** — RTDB 는 규칙에 선언되지 않은 경로의 쓰기를 전부 거부하므로, 미배포 상태에서는 `PERMISSION_DENIED` 가 난다.

- 붙여넣을 규칙 전문: **`docs/firebase-rules.md`** (저장소 `database.rules.json` 과 동일)
- 노드 2개를 쓴다 — `drill_rows`(추가 행) · `drill_overrides`(기본 행 수정·숨김)
- 값 검증도 규칙에 넣었다 — `inch` 0~4, `no` 1~200, `cleco` 4색 화이트리스트, `memo`/`photo` 길이 제한.
- 저장 실패 시 원인을 구분해 보여준다:

| 오류 | 화면 문구 |
|------|-----------|
| `PERMISSION_DENIED` | 권한이 없습니다 — 규칙에 `drill_rows` 가 배포됐는지 확인 |
| 네트워크 | 저장에 실패했습니다 (네트워크) |
| 그 외 | 원본 메시지 노출 |

> **A안(현재)의 한계:** 다른 노드와 마찬가지로 `.write: true` 다. 관리자 판별은 클라이언트에서만 이뤄지므로 DB 주소를 아는 사람은 API 로 직접 쓸 수 있다. 서버에서 막으려면 **B안 — Firebase Auth 도입**이 필요하며, 규칙 전문과 필요한 코드 변경·콘솔 설정은 `docs/firebase-rules.md` §B 에 정리했다. **모든 페이지를 건드리는 작업이라 별도 승인 후 진행한다.**

### 11.5.5 오프라인 안전장치
Firebase 는 **본문 스크립트와 분리된 `<script type="module">`** 에서 `try/catch` 로 동적 import 한다.

- 네트워크가 막히거나 Firebase 가 뜨지 않아도 **기본 56행 표·검색·시트·사진은 그대로 동작**한다.
- 이때 관리자 버튼만 나타나지 않는다(추가 행도 표시되지 않음).
- 검증: gstatic 차단 환경에서 `56 / 56 개` 정상 렌더, JS 오류 0건.

## 14. 운영 메모

- **메모·클리코·사진 추가**는 `info.html` 의 `EXTRA` 한 곳만 고치면 된다. 표 구조나 렌더 코드는 건드릴 필요 없다. 메모는 폰·PC 양쪽 표에 **바로 보인다.**
- **번호 범위 변경**은 `const MAX_NO = 40;` 한 줄. 올리면 작은 드릴이 되살아나고, 내리면 더 잘린다. 데이터 배열은 #80 까지 그대로 있다.
- 클리코 색은 현재 **4종(은색·구리색·검정·금색)** 만 정의돼 있다. 1/4″ 는 확인되지 않아 의도적으로 비워 뒀다 — 확정되면 `CLECO` 객체에 한 줄 추가하면 된다.
- 표의 지름 데이터(`NUMBER_DRILLS`)는 표준 규격이므로 수정할 일이 없다.
