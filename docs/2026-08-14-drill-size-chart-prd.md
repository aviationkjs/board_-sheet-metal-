## 1. 배경 / 요청 요약

현재 `info.html` 은 Huck Gun · Nose Assembly · Fastener 관계표 하나만 담고 있다. 여기에 현장에서 가장 자주 찾는 **드릴 사이즈 표**를 추가하려 한다. 사용자 요청은 네 가지다.

1. **Number size drill (No. 1~80) 표**를 넣는다. (원문 데이터 제공됨)
2. 여기에 **분수(Fraction) 사이즈**를 추가한다.
3. **행·열을 더 추가**한다. (mm 환산, 용도 등)
4. **추가한 열의 항목을 누르면 팝업이 뜨고 그 안에서 GIF로 내용을 볼 수 있게** 한다.
5. 전체를 **모바일에서 한눈에** 보이도록 반응형으로 만든다.

## 2. 되는 것 / 안 되는 것 (요청 검토 결과)

> **이 절이 이번 문서의 핵심입니다.** 여기 합의가 끝나야 나머지가 의미 있습니다.

### 2.1 ✅ 문제없이 되는 것

| # | 항목 | 근거 |
|---|------|------|
| 1 | No.1~80 + 분수 사이즈 통합 표 | 순수 정적 데이터. 제공해주신 80개 값은 ANSI 표준 규격과 전부 일치함을 대조 확인함 |
| 2 | mm 환산 · 근접 분수 · 정렬(지름순/번호순) 열 추가 | 계산으로 자동 생성. 데이터 입력 불필요 |
| 3 | 검색·필터 (숫자 입력 시 즉시 좁히기) | 라이브러리 없이 JS 20줄 수준 |
| 4 | **셀 클릭 → 팝업(모달) → GIF 재생** | 외부 라이브러리 없이 구현 가능. ESC·배경 탭·스와이프로 닫기 포함 |
| 5 | 팝업 열 때만 미디어 로드 (lazy) | 표 자체는 텍스트뿐이라 초기 로딩이 GIF 개수와 무관하게 빠름 |
| 6 | 반응형 (가로 스크롤 없이 375px 대응) | 기존 `divider.html` 에서 검증된 패턴 재사용 |
| 7 | 오프라인·로그인 불필요, GitHub Pages 그대로 동작 | 서버·DB 변경 없음 |

### 2.2 ⚠️ 되지만 조건이 붙는 것

| # | 항목 | 제약 | 제안 |
|---|------|------|------|
| 1 | **GIF 파일 자체** | 제가 만들 수 없습니다. 실제 작업 장면 촬영·편집은 사용자 몫입니다 | 우선 **자리표시자(placeholder)** 로 골격을 완성해 두고, 파일이 준비되는 대로 폴더에 넣기만 하면 자동 연결되게 설계 |
| 2 | **GIF 용량** | 5초짜리 720p GIF ≈ **5~15MB**. 20개면 100~300MB. GitHub 단일 파일 100MB 제한, 저장소 1GB 권장 한도. 이 저장소는 **이미 62MB** (FT-200 PDF 포함) | **MP4/WebM 변환을 강력 권장.** 같은 화질에 용량 1/10~1/20 (5초 ≈ 300KB~1MB) |
| 3 | MP4 로 바꾸면 "GIF" 가 아니게 되는가? | 아니요 — `<video autoplay loop muted playsinline>` 로 넣으면 **화면상 동작은 GIF와 완전히 동일**(무한 반복·소리 없음·자동 재생). 사용자는 차이를 느끼지 못합니다 | 확장자로 자동 분기하도록 만들어 **GIF·MP4·WebM 셋 다 지원**. 어느 쪽을 주셔도 동작 |
| 4 | 모바일 데이터 사용량 | GIF는 화질 자동조절이 없어 전체 파일을 그대로 받습니다 | 팝업을 열 때만 로드 + 파일당 목표 상한(§7.3) 설정 |
| 5 | GitHub Pages 대역폭 | 월 100GB 소프트 한도. 10MB GIF × 하루 100회 열람 = 월 30GB → 여유는 있으나 무한하지 않음 | 위 2·3번(용량 축소)으로 자연히 해결 |

### 2.3 ❌ 안 되는 것 (대안 포함)

| # | 요청 | 왜 안 되는가 | 대안 |
|---|------|-------------|------|
| 1 | **112행 전부를 폰 한 화면에 동시에** | 물리적 한계입니다. 375px 폭 · 660px 높이에 112행 × 6열을 넣으면 글자가 3px가 됩니다. "한눈에"를 문자 그대로는 만들 수 없습니다 | **§4의 2-뷰 구조로 근사합니다.** 원본 인쇄물처럼 4단 병렬 압축표를 기본값으로 두면 **80행이 20행 높이에** 들어가고, 폰에서 스크롤 1~2회로 전체가 잡힙니다 |
| 2 | 서버측 영상 스트리밍 / 화질 자동조절 | 정적 호스팅이라 서버가 없습니다 | 파일을 애초에 작게 만드는 것으로 해결 |
| 3 | GIF 안의 글자를 검색·확대·번역 | GIF·영상은 픽셀이라 텍스트가 아닙니다 | 팝업에 **HTML 텍스트 설명을 GIF와 나란히** 배치. 설명은 검색·복사·확대 가능 |
| 4 | GIF 없이도 완전 오프라인 | 미디어는 최초 1회 네트워크가 필요합니다 | 표·계산은 100% 오프라인 동작. 미디어 캐시는 PWA로 v2에서 |
| 5 | 열을 무제한 추가 | 열이 8개를 넘으면 폰에서 어떤 방식으로도 읽히지 않습니다 | **§5의 8열을 상한으로 제안.** 그 이상은 팝업 안으로 보냅니다 |

## 3. 목표 / 비목표

### 목표
1. No.1~80 **및** 분수 사이즈를 **하나의 지름 순 표**로 통합해 "이 리벳엔 어떤 드릴?"을 한 번에 답한다.
2. 인치 소수 ↔ mm ↔ 근접 분수를 **동시에** 보여 현장 환산 단계를 없앤다.
3. 리벳 규격·클리코 색 등 **판금 실무 정보**를 열로 붙인다.
4. 해당 항목의 **작업 요령을 GIF/짧은 영상 팝업**으로 즉시 확인한다.
5. 모바일 우선. 로그인 불필요, 오프라인 동작(미디어 제외).

### 비목표
1. 탭 드릴 / 나사 하부 구멍(tap drill) 표 — v2 이관.
2. 회전수(RPM)·이송 계산기 — 별도 기능.
3. Firebase 연동·사용자별 저장 — 이 페이지는 읽기 전용 참조표.
4. 기존 Huck Fastener 표 삭제 — **유지**하고 드릴 표를 아래에 추가한다.

## 4. 핵심 설계 — "한눈에" 와 "열 추가" 의 충돌 해결

두 요청은 서로 정면으로 충돌합니다.

- **한눈에 보려면** → 열이 적어야 하고 행이 압축돼야 함 (원본 인쇄물이 `No.|Dia.` 2열을 4단 병렬로 놓은 이유)
- **열을 추가하려면** → 행마다 정보가 늘고 세로로 길어짐 (한눈에 보기 불가)

**해결: 뷰 모드 토글 2종.** 같은 데이터, 두 가지 표현.

### 4-1. 차트 모드 (기본값) — "한눈에"
원본 인쇄물 레이아웃 그대로. `No. | Dia.` 2열 쌍을 화면 폭에 맞춰 병렬 배치한다.

```
┌ No.│ Dia. ┬ No.│ Dia. ┬ No.│ Dia. ┬ No.│ Dia. ┐
│  1 │.2280 │ 21 │.1590 │ 41 │.0960 │ 61 │.0390 │
│  2 │.2210 │ 22 │.1570 │ 42 │.0935 │ 62 │.0380 │
│  3 │.2130 │ 23 │.1540 │ 43 │.0890●│ 63 │.0370 │
   …        …          …          …
│ 20 │.1610 │ 40 │.0980●│ 60 │.0400 │ 80 │.0135 │
└──────────┴──────────┴──────────┴──────────────┘
             ● = 작업 GIF 있음 (탭하면 팝업)
```

- **PC**: 4단 → 80행이 20행 높이에 들어감
- **태블릿**: 3단
- **폰(≤600px)**: 2단 → 40행 높이. 스크롤 1~2회로 전체 파악
- 어느 셀이든 **탭하면 하단 시트(bottom sheet)** 가 올라오며 mm·근접 분수·리벳 용도·GIF를 보여준다 → **열을 늘리지 않고도 정보를 다 담는 방법**
- 헤더 행은 `position: sticky` 로 고정

### 4-2. 상세 모드 — "열 추가"
전체 열을 가진 세로 표. 검색·정렬·필터가 여기서 동작한다.

```
구분 │ 표기  │ inch  │ mm   │ 근접분수 │ 리벳/용도        │ 클리코 │ GIF
No.  │ #40   │ .0980 │ 2.49 │ 3/32″    │ AD3 3/32″ 리벳   │ 🩶 은색 │ ▶
Frac │ 1/8″  │ .1250 │ 3.18 │ —        │ —                │        │
No.  │ #30   │ .1285 │ 3.26 │ 1/8″     │ AD4 1/8″ 리벳    │ 🟤 구리 │ ▶
```

- 모드 전환은 툴바 토글 한 번. 선택은 `localStorage` 저장.

## 5. 데이터 사양

### 5.1 행 (Rows)

| 분류 | 개수 | 범위 | 상태 |
|------|------|------|------|
| Number drill | **80** | #1 (.2280) ~ #80 (.0135) | ✅ 제공됨. 표준값과 전량 대조 완료 |
| Fraction drill | **32** | 1/64″ (.0156) ~ 1/2″ (.5000), 1/64 간격 | ✅ 계산으로 생성 가능 |
| Letter drill (선택) | 26 | A (.2340) ~ Z (.4130) | ⬜ **넣을지 확인 필요** (§14-1). 1/4″ 리벳용 F 드릴이 여기 속함 |
| **합계** | **112 (또는 138)** | | |

### 5.2 열 (Columns)

| # | 열 | 출처 | 차트 모드 | 상세 모드 | 비고 |
|---|-----|------|:--------:|:--------:|------|
| 1 | 구분 (No./Frac/Letter) | 자동 | 배지 | ✅ | 색 배지로 구분 |
| 2 | 표기 (`#30`, `1/8″`) | 자동 | ✅ | ✅ | |
| 3 | 소수 인치 | 제공 데이터 | ✅ | ✅ | 4자리 고정 (`.1285`) |
| 4 | mm | 자동 (×25.4) | 시트 | ✅ | 2자리 (`3.26`) |
| 5 | 근접 분수 (오차 병기) | 자동 | 시트 | ✅ | `1/8″ (−.0035)` |
| 6 | **리벳 / 용도** | **입력 필요** | 시트 | ✅ | ⬜ §14-2 |
| 7 | **클리코 색** | **입력 필요** | 시트 | ✅ | ⬜ §14-3 |
| 8 | **작업 GIF** | **파일 필요** | ● 마커 | ▶ 버튼 | ⬜ §14-4 — **팝업 트리거 열** |

> 6·7·8번이 이번 요청의 "추가하는 열"이고, 8번이 "누르면 팝업이 뜨는" 열입니다. 6·7번 내용과 8번 파일은 제가 만들어낼 수 없어 회신이 필요합니다.

### 5.3 데이터 저장 형식

`info.html` 안에 인라인 JS 배열로 둔다. (외부 JSON fetch는 `file://` 로 열 때 CORS로 막히므로 인라인이 안전)

```js
const DRILLS = [
  { type:"no",   label:"#40",  dec:0.0980, use:"AD3 3/32″ 리벳", cleco:"silver", clip:"ad3-rivet" },
  { type:"frac", label:"1/8″", dec:0.1250, num:1, den:8 },
  { type:"no",   label:"#30",  dec:0.1285, use:"AD4 1/8″ 리벳",  cleco:"copper", clip:"ad4-rivet" },
  …
];
```

- `clip` 이 있는 항목만 팝업 아이콘이 뜬다. **없으면 자동으로 숨김** → 파일이 하나도 없어도 표는 정상 동작.
- 나중에 GIF를 추가할 때 **`clip` 한 줄만 적으면** 끝나도록 설계.

## 6. GIF 팝업 사양

### 6.1 동작
1. 셀의 `▶` (또는 차트 모드의 `●`) 를 탭
2. 화면 중앙에 모달, 배경은 어둡게 흐림 처리
3. 모달 구성: **제목 / 미디어 / 텍스트 설명 / 관련 사이즈 / 닫기**
4. 닫기: `X` 버튼 · 배경 탭 · `ESC` 키 · 모바일 아래로 스와이프
5. 모달이 열려 있는 동안 뒤 페이지 스크롤 잠금, 닫으면 원래 스크롤 위치 복귀
6. 미디어는 **모달을 여는 순간 처음 로드** (초기 페이지 로딩과 무관)
7. 로딩 중 스피너, 실패 시 "영상을 불러오지 못했습니다" + 텍스트 설명은 그대로 표시

### 6.2 미디어 형식 자동 분기

| 확장자 | 렌더링 | 권장도 |
|--------|--------|--------|
| `.mp4` / `.webm` | `<video autoplay loop muted playsinline>` | ⭐ **권장** — GIF와 화면상 동일, 용량 1/10~1/20 |
| `.gif` | `<img>` | 가능 — 용량 큼 |
| `.png` / `.jpg` | `<img>` | 정지 이미지도 지원 |

파일명 확장자만 보고 코드가 알아서 갈라집니다. **어느 형식을 주셔도 됩니다.**

### 6.3 파일 배치 규칙

```
assets/clips/
  ad3-rivet.mp4      ← 3/32" 리벳 작업
  ad3-rivet.txt      ← (선택) 텍스트 설명
  deburr.mp4
  cleco-use.mp4
```

- 파일명 = 데이터의 `clip` 값. 폴더에 넣고 `clip:"ad3-rivet"` 만 적으면 연결됨.
- 자리표시자: 파일이 아직 없으면 "준비 중" 안내 카드를 대신 표시 → **깨진 화면 없음**.

### 6.4 용량 가이드 (권장 상한)

| 항목 | 권장 | 최대 |
|------|------|------|
| 클립 길이 | 3~6초 | 10초 |
| 해상도 | 720×720 이하 | 1080p |
| 파일당 용량 | **1MB 이하 (MP4)** | 3MB |
| 전체 클립 수 | 10~20개 | 40개 |
| 전체 합계 | **20MB 이하** | 100MB |

> MP4 변환 명령 예시 (참고용): `ffmpeg -i in.mov -t 5 -vf scale=720:-2 -crf 30 -an out.mp4`

```

│   ┌ 툴바 [🔍 검색____] [차트|상세] [inch|mm] [전체|No.|분수|리벳용]
```

### 7.1 반응형 기준

| 폭 | 차트 모드 단 수 | 상세 모드 |
|----|----------------|-----------|
| ≥1000px | 4단 | 전체 8열 |
| 600~999px | 3단 | 8열 (패딩 축소) |
| ≤599px | **2단** | 카드형 2행 접기 또는 5열(구분·mm 숨김) |

- body 가로 스크롤 없음 (375px 기준 검증)
- 표 헤더 `sticky`, 툴바도 `sticky`
- 탭 영역 최소 44×44px (장갑 낀 손 고려)
- 숫자는 고정폭 폰트(`IBM Plex Mono`)로 자릿수 정렬

### 7.2 테마 — ⬜ 확인 필요 (§14-5)

현재 `info.html` 은 **밝은 테마**(`#f4f7f9`)이고, `remove_list.html`·`divider.html`·`duty_roster.html` 은 **산업용 다크 테마**(`#16181c` + 앰버)입니다. 사이트 통일감을 위해 다크로 맞출지, 현장 밝은 곳 가독성을 위해 밝은 테마를 유지할지 결정이 필요합니다.

## 8. 검색 · 필터 · 정렬

| 기능 | 동작 |

## 9. 데이터 정확성

- 제공하신 No.1~80 값 80개를 ANSI 표준 번호 드릴 규격과 **전량 대조했고 전부 일치**합니다. 그대로 사용합니다.
- 분수 값은 코드에서 `num/den` 으로 계산해 넣으므로 오타 가능성이 없습니다.
- mm·근접 분수는 계산 결과이므로 검증 불필요.
- **리벳/클리코 열만 출처 확인이 필요합니다** (§14-2, §14-3). 확실하지 않은 값을 임의로 채워 넣지 않겠습니다 — 현장에서 잘못된 드릴을 잡으면 소재를 버리기 때문입니다.

## 10. 기술 스택

- 외부 라이브러리 **없음** (모달·표·검색 전부 직접 구현)

- Firebase·DB 규칙 변경 **없음**
- 로그인 불필요 (`divider.html` 과 동일 정책)
