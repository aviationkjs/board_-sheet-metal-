# PRD — 공지·답글·달력 (스티커 보드 확장)

| 항목 | 내용 |
|------|------|
| 문서명 | 성능보드판 — 공지 전달 · 답글 · 달력 |
| 버전 | v1.0 (1~2단계) |
| 작성일 | 2026-11-24 |
| 대상 파일 | `index.html`, `notice.js`(신규), `style.css`, `app.js`, `admin.html`, `logs.html`, `database.rules.json` |
| 인프라 | GitHub Pages 정적 호스팅 + Firebase Realtime Database(Spark 무료), 서버 없음 |
| 상태 | 1~2단계 구현 완료 · **DB 규칙 게시 필요** |

---

## 1. 배경

대문이 스티커 한 종류(`notes`)뿐이라 **공지를 전달하는 자리**가 없었다. 스티커는 모두 동등한 메모라서

- 누가 쓴 공지 하나에 여러 사람이 답하는 **상하 관계**를 표현할 수 없고,
- 공지의 핵심인 **"봤는지"** 를 확인할 수 없으며(좋아요뿐),
- 제목이 없어 목록에서 훑어볼 수 없다.

여기에 "언제 무슨 일이 있는지"를 같이 보려면 날짜 축이 필요하다. 그래서 **공지 · 답글 · 달력**을 더하되, 쓰던 스티커는 그대로 둔다.

## 2. 목표 / 비목표

### 목표
1. 대문을 **공지 / 달력 / 스티커 3탭**으로 재구성한다. 첫 화면은 공지.
2. 공지는 **관리자·공지 부관리자만** 쓰고, **답글은 전원** 달 수 있다.
3. **읽음 확인** — 누가 읽었는지 기록하고, 안 읽은 공지 수를 탭에 배지로 띄운다.
4. 공지에 날짜를 달면 **달력에 자동 표시**되고, 공지와 무관한 **독립 일정**도 등록할 수 있다.
5. 기존 스티커(`notes`)는 **데이터·동작 모두 그대로** 유지한다.

### 비목표
1. 휴대폰 푸시 알림 — 정적 호스팅 + 무료 요금제로는 발송 서버를 둘 수 없다(§7).
2. 공지 첨부파일·이미지 업로드.
3. 사역표(`duty`)·간트(`gantt`) 일정을 달력에 겹쳐 보기 → 4단계로 미룸.
4. Firebase Auth 도입 — 로그인 체계를 바꾸는 별도 과제(§7).

## 3. 데이터 모델 (새 노드 3개)

```
notices/{id}
  title       제목 (1~60자)
  body        본문 (~2000자)
  author      작성자            ← 생성 후 변경 불가(규칙)
  createdAt / updatedAt / updatedBy
  level       'normal' | 'important'
  pinned      상단 고정 여부
  dateFrom    일정 시작 YYYY-MM-DD (선택)  ← 있으면 달력에 뜸
  dateTo      일정 종료 YYYY-MM-DD (선택)
  readers/{사용자}: 읽은 시각
  replyCount  답글 수 (목록용 비정규화 값)
  archived / archivedBy / archivedAt      ← 보관(삭제 대신)

replies/{공지id}/{답글id}
  user, text (1~500자), createdAt

events/{id}
  title (1~40자), date, endDate(선택), color, author, createdAt/updatedAt
```

**답글을 공지 안이 아니라 밖으로 뺀 이유**: 대문은 `notices`만 구독하므로 목록이 가볍고, 답글은 그 공지를 펼칠 때만 읽는다. 공지가 쌓여도 첫 화면 로딩이 느려지지 않는다.

## 4. 권한

| 역할 | 판정 | 할 수 있는 일 |
|------|------|----------------|
| 주관리자 | `username === 'admin'` | 전부 |
| 공지 부관리자 | `users/{id}.noticeAdmin === true` | 공지 작성·수정·보관, **모든 일정** 수정·삭제, 남의 답글 삭제 |
| 전원 | 로그인한 사용자 | 공지 읽기, 답글 작성, **본인 답글** 삭제, **일정 등록**과 **본인 일정** 수정·삭제 |

> 일정(`events`)은 2026-11-24 기준 **전원 등록 가능**으로 열었다. 대신 고치고 지우는 것은 올린 사람(`author`)과 담당자만 할 수 있고, 달력의 날짜 목록에 **올린 사람 이름이 함께 표시**된다. 공지는 담당자 전용 그대로다.

- `dutyAdmin`(사역표) · `materialAdmin`(자재소모)과 **같은 패턴**이다. `admin.html` 회원 관리 표에 `공지` 버튼을 추가했고, 다른 영역과 마찬가지로 **영역당 한 명**만 지정된다(지정 시 기존 담당자 자동 해제).

## 5. 화면

```
┌ 헤더   성능보드판 [이름]            [+ 공지 / + 일정 / + 스티커] [⋯]
├ 탭     [공지 ②] [달력] [스티커]        ← 탭에 따라 헤더 버튼이 바뀜
│
│ 공지   [새 글][중요][고정][11/26~11/27] 제목
│        작성자 · 날짜
│        본문(2줄 접힘 → 누르면 펼침)
│        [읽음 7] [답글 2]            [수정] [보관]
│        └ 펼치면: 답글 목록 + 한 줄 입력칸(Enter 등록)
│
│ 달력   ‹ 2026년 11월 › [오늘]        ☑공지 일정 ☑일정
│        7열 월 그리드 — 날짜마다 일정 띠
│        아래: 고른 날짜의 목록 → [공지 보기] / [수정]
│
└ 스티커  기존 보드 그대로
```

- **안 읽은 공지**: 왼쪽 파란 띠 + `새 글` 배지 + 탭 배지 숫자. 펼치면 읽음 처리.
- **중요 공지**: 왼쪽 빨간 띠 + `중요` 배지. 고정 공지는 항상 맨 위.
- **보관**: 삭제 대신 보관함으로. 담당자만 `보관함 보기`로 꺼내 복구할 수 있다.
- **반응형**: 휴대폰(≤600px)에서는 달력 일정 띠가 **점**으로 바뀌고, 날짜를 누르면 아래 목록에서 전체 제목을 본다. 가로 스크롤 없음.
- 색·글자·간격은 전부 `tokens.css`를 그대로 쓴다. 외부 라이브러리 없음(폐쇄망·CSP 안전).

## 6. 구현 구조

| 파일 | 역할 |
|------|------|
| `notice.js` (신규, ~470줄) | 탭 전환, 공지 목록·작성·수정·보관, 답글, 달력, 일정 |
| `app.js` | **스티커 전용으로 그대로 유지**. 글자 깨짐·스크립트 주입 방지용 `esc()` 한 곳만 추가 |
| `index.html` | 탭 구조, 패널 3개, 공지·일정 입력 대화상자 |
| `style.css` | 탭·공지·달력·대화상자 스타일 (기존 스티커 스타일 손대지 않음) |

`notice.js`는 다른 단일 페이지들처럼 **자기 Firebase 설정을 따로 가지되**, `getApps()`로 `app.js`가 만든 앱을 재사용한다(중복 초기화 방지).

## 7. 제약 (반드시 알아야 할 것)

**① DB 규칙을 게시해야 저장된다.** Realtime Database는 규칙에 없는 경로의 쓰기를 전부 거부한다. `database.rules.json`에 `notices`·`replies`·`events`를 추가했으므로, **Firebase 콘솔 → Realtime Database → 규칙**에 `docs/firebase-rules.md`의 A안을 다시 붙여넣고 게시해야 한다. 안 하면 공지 작성·답글·일정 저장이 모두 거부된다(화면에 그 안내가 뜨도록 해 두었다).

**② 규칙으로 작성자 위조를 막을 수는 없다.** 로그인이 Firebase Auth가 아니라 `localStorage` 이름이라, 규칙이 "누가" 쓰는지 검증할 수단이 없다. 현재 사역표·자재소모와 같은 수준이며, 대신 이렇게 낮춰 두었다.
- `author` / `user` 필드는 **생성 후 변경 불가**(규칙)
- 길이·형식 검증 (제목 60자, 본문 2000자, 답글 500자, 날짜 `YYYY-MM-DD`)
- 수정 시 `updatedBy`·`updatedAt` 기록 + `logs`에 전부 남김
- 삭제 대신 **보관** → 사라진 공지를 추적할 수 있음

제대로 막으려면 Firebase Auth 도입이 필요하다(`docs/firebase-rules.md` B안).

**③ 푸시 알림은 불가.** 대신 **안 읽은 공지 배지**와 **읽음 N명** 표시로 전달 여부를 확인한다.
