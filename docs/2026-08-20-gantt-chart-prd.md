## 1. 배경 · 목적

과목별 학습 일정을 표나 메모로 관리하면 **한 과목이 밀렸을 때 뒤 일정을 전부 손으로 다시 계산**해야 한다. 실제로는 "국어가 이틀 밀렸다" → 수학·영어·사회·과학의 시작일을 하나씩 고쳐 적는 작업이 반복된다.

이를 **블록을 밀면 뒤 일정이 따라 움직이는 간트차트**로 해결한다.

- 보드 사용자 **누구나** 웹에서 블록을 끌어 일정을 바꾼다.
- 앞 과업을 옮기면 **뒤 과업이 자동으로 같이 이동**한다.
- 변경은 즉시 모든 사람 화면에 반영된다(실시간).

## 2. 목표 / 비목표

### 목표
1. 국어·수학·영어·사회·과학 5과목 일정을 한 화면에서 본다.
2. 블록을 **좌우로 끌어 시작일 변경**, **끝을 끌어 기간 변경**.
3. 선행 과업이 움직이면 **후속 과업이 규칙에 따라 자동 이동**.
4. 로그인한 사람은 누구나 편집, 변경 사항은 실시간 공유.
5. 모바일(세로)에서도 손가락으로 조작 가능.
6. 누가 언제 무엇을 바꿨는지 남기고, 되돌릴 수 있다.

### 비목표 (이번 범위 아님)
- 리소스(담당자) 배정 · 공수 계산
- 임계 경로(Critical Path) 분석
- 여러 개의 프로젝트/보드 관리 — **하나의 공용 일정표**만 둔다
- 엑셀 가져오기/내보내기

## 3. 진입 경로

보드 상단 **더보기(⋯) → 📅 학습 간트차트** → `gantt.html`

기존 게임·균등분할 계산기와 동일한 패턴이다. 로그인(`localStorage.username`) 없으면 `auth.html`로 보낸다.

## 4. 핵심 개념

### 4.1 과업(Task)

기본 5개로 시작한다.

| 과업 | 기본 기간 | 색 |
|---|---|---|
| 국어 | 5일 | 파랑 |
| 수학 | 7일 | 주황 |
| 영어 | 5일 | 초록 |
| 사회 | 4일 | 보라 |
| 과학 | 4일 | 청록 |

시작일 기본값은 **차트를 처음 만든 날(오늘)** 부터 순서대로 이어 붙인다.

### 4.2 의존 관계(Dependency)

기본은 **한 줄 체인**이다.

```
국어 ──▶ 수학 ──▶ 영어 ──▶ 사회 ──▶ 과학
```

- 종류는 **FS(선행 종료 → 후속 시작)** 한 가지만 쓴다.
- 각 의존은 **간격(lag, 일)** 을 가진다. 기본 0일(선행이 끝난 다음 날 시작).
- 한 과업이 여러 선행을 가질 수 있다(향후 확장). 이 경우 **가장 늦은 선행** 기준으로 계산한다.
- **순환 금지** — 의존을 바꿀 때 사이클이 생기면 거부한다.

### 4.3 자동 이동 규칙 ★핵심

두 가지 모드를 두고, **기본값은 「간격 유지」**로 한다.

| 조작 | 간격 유지 (기본) | 겹침 방지 |
|---|---|---|
| 국어를 뒤로 3일 밀기 | 수학·영어·사회·과학 **모두 3일씩 밀림** | 겹치는 만큼만 밀림 (결과적으로 3일) |
| 국어를 앞으로 3일 당기기 | 뒤 과업 **모두 3일씩 당겨짐** | **아무 변화 없음** (틈만 생김) |
| 국어 기간을 2일 늘리기 | 뒤 과업 모두 2일씩 밀림 | 겹치는 만큼 밀림 |
| 수학만 따로 뒤로 밀기 | 영어 이후가 따라 밀리고, **국어–수학 간격이 늘어난 채로 기억됨** | 영어 이후가 겹칠 때만 밀림 |

- **간격 유지**: 의존에 저장된 lag를 항상 보존한다. 블록들이 고무줄로 묶인 것처럼 움직인다. 학습 계획처럼 "쭉 이어서 하는" 일정에 맞는다.
- **겹침 방지**: 겹칠 때만 민다. 일정에 여유를 두고 싶을 때 쓴다.
- 사용자가 **후속 과업을 직접 끌면** 그 과업의 lag가 새 값으로 갱신된다(= 의도적으로 틈을 벌린 것으로 본다).
- 전파는 **위상 정렬 순서로 1회** 계산한다. 재귀 호출로 같은 노드를 여러 번 갱신하지 않는다.
- 계산 결과는 **한 번의 multi-path update로 원자적 저장**한다(중간 상태가 남지 않게).

### 4.4 날짜 규칙

- 최소 단위 **1일**, 드래그 스냅도 1일.
- 기간은 **1~365일**.
- 기본은 **주말 포함**(달력일 기준). 설정에서 `주말 건너뛰기`를 켜면 토·일을 기간에서 제외한다.
- 과거 날짜로도 옮길 수 있다(하한 없음).
- 날짜는 `YYYY-MM-DD` 문자열로 저장한다. 타임존 문제를 피하기 위해 **시각·UTC 변환을 쓰지 않는다.**

```
│ 과목(고정)│ 8/20 8/21 8/22 8/23 …   (가로 스크롤)      │
│ 국어      │ ▓▓▓▓▓▓▓▓▓▓                                 │
│ 수학      │           ▓▓▓▓▓▓▓▓▓▓▓▓▓▓                   │
│ 영어      │                         ▓▓▓▓▓▓▓▓▓▓         │

│ 과학      │                                            │

```

- **좌측 과목 열은 가로 스크롤에도 고정**(sticky).
- 날짜 헤더에 월·일·요일. **주말은 배경을 다르게**, **오늘은 세로선으로 강조**.
- 블록에는 과목명과 `기간(일)`을 표시하고, 폭이 좁으면 툴팁으로 보여준다.
- 블록 우측 끝에 **리사이즈 핸들**.

## 6. 조작 방식

| 동작 | 데스크톱 | 모바일 |
|---|---|---|
| 시작일 이동 | 블록을 좌우로 드래그 | 블록을 **길게 눌러(250ms)** 드래그 |
| 기간 조절 | 우측 끝 핸들 드래그 | 핸들 드래그 (터치 영역 44px 이상) |
| 타임라인 이동 | 가로 스크롤 / 휠 | 좌우 스와이프 |
| 세부 편집 | 블록 클릭 → 시트 | 블록 탭 → 시트 |

- **모바일에서 롱프레스를 요구하는 이유**: 짧은 스와이프는 타임라인 스크롤과 구분이 안 된다. 롱프레스로 "이제 블록을 잡았다"를 명확히 하고, 이때 **햅틱(진동)** 과 블록 그림자로 피드백을 준다.
- 드래그 중 **뒤 과업이 어디로 갈지 반투명 고스트로 미리 표시**한다. 놓기 전에 결과를 알 수 있어야 한다.
- 드래그 중 상단에 `국어 8/20 → 8/23 (+3일)` 형태로 변화량을 띄운다.
- **키보드 접근성**: 블록을 Tab으로 선택한 뒤 `←`/`→` 1일 이동, `Shift + ←/→` 기간 조절, `Enter` 세부 편집.

## 7. 데이터 설계 (Firebase RTDB)

경로: `gantt`

```
gantt/
  tasks/
    korean : { name:"국어", order:0, start:"2026-08-20", days:5, color:"#3498db",
               deps:{ }, updatedAt:1755..., updatedBy:"홍길동" }
    math   : { name:"수학", order:1, start:"2026-08-25", days:7, color:"#e67e22",
               deps:{ korean:0 }, ... }
    english: { name:"영어", order:2, start:"2026-09-01", days:5, color:"#2ecc71",
               deps:{ math:0 }, ... }
    social : { name:"사회", order:3, start:"2026-09-06", days:4, color:"#9b59b6",
               deps:{ english:0 }, ... }
    science: { name:"과학", order:4, start:"2026-09-10", days:4, color:"#1abc9c",
               deps:{ social:0 }, ... }
  settings: { mode:"rigid", skipWeekend:false, updatedAt, updatedBy }
  locks/{taskId}: { by:"홍길동", at:1755... }     // 드래그 중 소프트 락
  history/{ts}  : { user, action, taskId, before:{...}, after:{...} }
```

- `deps`는 **`{선행과업id: 간격일수}` 맵**이다. 배열이 아니라 맵을 쓰는 이유는 RTDB에서 배열 동시 수정이 위험하기 때문이다.
- `history`는 **최근 50건만** 유지한다(되돌리기·감사용).
- 과업 id는 영문 소문자 고정키(`korean`, `math`, …)를 쓴다. 이름을 바꿔도 의존 관계가 깨지지 않는다.

### 보안 규칙 추가분

```json
"gantt": {
  ".read": true,
  ".write": true,
  "tasks": {
    "$id": {
      "name":  { ".validate": "newData.isString() && newData.val().length <= 20" },
      "start": { ".validate": "newData.isString() && newData.val().matches(/^[0-9]{4}-[0-9]{2}-[0-9]{2}$/)" },
      "days":  { ".validate": "newData.isNumber() && newData.val() >= 1 && newData.val() <= 365" },
      "order": { ".validate": "!newData.exists() || newData.isNumber()" },
      "color": { ".validate": "!newData.exists() || (newData.isString() && newData.val().length <= 9)" },
      "$other": { ".validate": true }
    }
  }
}
```

## 8. 동시 편집 처리

여러 명이 같은 화면을 보고 있으므로 충돌 처리가 필요하다.

1. **실시간 반영** — `onValue` 구독. 다른 사람 변경이 즉시 화면에 나타난다.
2. **소프트 락** — 드래그를 시작하면 `locks/{taskId}`에 본인 이름을 쓴다.
   - 다른 사람에게는 그 블록이 `🔒 홍길동 수정 중`으로 보이고 잡히지 않는다.
   - **10초 만료** — 브라우저가 죽어도 락이 영구히 남지 않는다.
   - `onDisconnect().remove()`로 연결이 끊기면 자동 해제한다.
3. **원자적 저장** — 전파 결과(여러 과업의 start)를 **한 번의 `update()`** 로 보낸다.
4. **드래그 중 원격 변경** — 내가 잡고 있는 블록 외의 변경은 즉시 반영하되, **내가 놓는 순간 최신 상태로 다시 전파 계산**해서 저장한다.
5. **되돌리기** — `history` 최근 항목을 되돌린다. 본인이 만든 변경만, **5분 이내**로 제한한다.

## 11. 반응형 · 성능

- 과업 5~20개 수준이므로 **DOM 렌더로 충분**하다. 캔버스·외부 라이브러리 불필요.
- 하루 폭은 **일 보기 40px / 주 보기 14px** 두 단계. 모바일 기본은 주 보기.
- 모바일 세로에서 과목 열 88px 고정 + 나머지 타임라인.
- 드래그 중에는 `transform: translateX()` 만 바꿔 리플로우를 피한다.

## 부록 A. 전파 알고리즘 (의사코드)

```js
// 1) 위상 정렬 — 순환이 있으면 즉시 중단
const order = topoSort(tasks);          // deps 기준

// 2) 사용자가 직접 옮긴 과업은 고정(anchor)하고 나머지를 계산
function propagate(tasks, movedId, mode) {
  const next = structuredClone(tasks);
  for (const id of order) {
    if (id === movedId) continue;       // 직접 옮긴 건 사용자의 뜻이므로 유지
    const deps = next[id].deps || {};
    let earliest = null;
    for (const [depId, lag] of Object.entries(deps)) {
      const depEnd = addDays(next[depId].start, next[depId].days);  // 종료 다음 날
      const cand = addDays(depEnd, lag);
      if (earliest === null || cand > earliest) earliest = cand;
    }
    if (earliest === null) continue;    // 선행 없음
    if (mode === "rigid")      next[id].start = earliest;                  // 항상 붙인다
    else if (next[id].start < earliest) next[id].start = earliest;         // 겹칠 때만 민다
  }
  return next;
}

// 3) 후속 과업을 사용자가 직접 끌었다면 lag를 갱신해 그 간격을 기억한다
function rememberLag(tasks, movedId) {
  for (const [depId, _] of Object.entries(tasks[movedId].deps || {})) {
    const depEnd = addDays(tasks[depId].start, tasks[depId].days);
    tasks[movedId].deps[depId] = diffDays(depEnd, tasks[movedId].start);   // 음수 방지 필요
  }
}
```

**주의점**
- `addDays`는 `YYYY-MM-DD` 문자열 기준으로 계산한다. `new Date()` + 시각을 섞으면 서머타임·타임존에서 하루가 어긋난다.
- lag가 음수가 되는 경우(선행이 끝나기 전에 시작) — 허용할지 말지 결정 필요. **기본은 0으로 하한**을 둔다.
- 주말 건너뛰기가 켜져 있으면 `addDays`를 **영업일 기준 함수로 교체**한다. 두 계산을 섞지 않는다.
